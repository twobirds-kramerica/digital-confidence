## Finding 1 — Flat "All Lessons" sidebar violates Choices and Disclosure principles (P1)

**System:** Organisation + Navigation  
**Dan Brown principle violated:** #2 Choices, #3 Disclosure  

**Observation:** The sidebar navigation has two sections: "Get Started" (Home, Foundations, Set Up for a Loved One, DCC Kids — 4 items) and "All Lessons" (30+ module links in a flat unbroken list). The "All Lessons" section provides zero sub-grouping.

**Problem:** The DCC homepage (`index.html`) uses a five-accordion structure — "Begin Here", "Safety First", "Daily Life", "Staying Independent", and one additional group — to progressively disclose modules. This accordion structure is the only taxonomy the product has. The sidebar discards it entirely and exposes all 30+ items at once as a flat list.

A senior user who enters from a module page (Google result, shared link) and looks at the sidebar sees an undifferentiated wall of links. They cannot orient: "Am I in the right section? Have I done this?" The five-category taxonomy exists; it is just not applied to the sidebar.

**Fix direction:** Apply the homepage accordion categories as sub-groups in the sidebar. The "All Lessons" section becomes five collapsible or labelled groups matching the homepage structure. This does not add new content — it applies existing taxonomy to the navigation system.

**Effort estimate:** Medium (one sidebar HTML + CSS change, applied to global include or all module pages).

## Finding 2 — Module labelling uses three incompatible naming schemes (P1)

**System:** Labelling  
**Dan Brown principle violated:** #7 Focused Navigation  
**WCAG criterion:** 3.2.3 Consistent Navigation, 3.2.4 Consistent Identification  

**Observation:** Module slugs and page titles use three distinct schemes:
- Numeric theme: `module-1` → "The Escape Hatch", `module-2` → "Mastering Your Home Screen"
- Decimal numeric: `module-2-5` → "Everyday Tasks"
- Descriptive-only (no number): `module-fact-check`, `module-ai-health`, `module-visual-ai`

**Problem:** Users cannot predict the URL from the label or the label from the URL. Screen readers encounter inconsistent link text patterns. The `module-2-5` slug suggests a half-module or insert, creating false hierarchy. Modules without numbers cannot be ordered mentally by users who learned the sequence.

**Additionally:** Module 8 is titled "Stay Connected"; Module 18 is titled "Staying Connected". These are near-identical labels for different content. A user scanning the sidebar list cannot distinguish them.

**Fix direction:** Adopt a single canonical labelling scheme: descriptive-primary with optional numeric suffix in parentheses for users who want sequence context. Retire `module-2-5` slug. Rename one of the "Stay Connected" / "Staying Connected" modules to unambiguously distinguish them (e.g., "Staying Connected with Family" vs "Video Calling Basics").

**Effort estimate:** Medium-High (requires slug redirects if URLs change; can be done as label-only change first without URL changes).

## Finding 3 — No search: 30+ modules with zero findability mechanism (P1)

**System:** Search  
**Dan Brown principle violated:** #6 Multiple Classification  
**Senior-specific risk:** High — seniors frequently enter DCC with a task goal ("how do I pay a bill") not a module number  

**Observation:** `sitemap.xml` confirms 40+ page URLs. The sidebar lists 30+ module links. There is no search input field on any page. There is no filter, tag system, or topic index.

**Problem:** A senior who wants to find "banking" or "video calling" must scan all 30+ sidebar items by label, hoping the label matches their mental model of the task. If they entered from a specific module (e.g., a library printed QR code for Module 5), they have no mechanism to find other relevant content.

The DCC homepage accordion partially addresses this for first-time visitors, but the accordion is not accessible from module pages. There is no path from "I'm on Module 12, I want to find the video calling module" to finding it without going back to the homepage and scanning.

**Fix direction:** Option A (minimal): add a topic/keyword index page (`/topics.html`) linked from the sidebar. Option B (full): implement browser-side search using a static JSON index (no backend, no npm — plain JS `fetch()` against a pre-built `search-index.json`). Option B is preferred per SIMPLICITY FIRST — a static JSON approach is one script, no dependencies.

**Effort estimate:** Option A = Low; Option B = Medium.

## Finding 4 — French IA is a stub: no language switcher, no structural parity (P2)

**System:** Organisation + Navigation  
**Dan Brown principle violated:** #5 Front Doors  
**WCAG criterion:** 3.1.2 Language of Parts  
**Regulatory risk:** Canada.ca bilingual parity principle; OG description claims "bilingual"  

**Observation:** `sitemap.xml` lists `fr/index.html` and `fr/modules.html`. The English sidebar has no language switcher. The French pages exist but are not reachable from the English global navigation.

**Problem:** The DCC product description and the OG meta tags (confirmed in DESIGN-SYSTEM.md) position DCC as a bilingual Canadian programme. The IA does not deliver this. A French-speaking senior visiting the site has no discoverable path to French content from any English page. The French section exists as a hidden stub.

Additionally, the `fr/` section does not appear to have its own sidebar navigation structure mirroring the English one — it is an isolated page, not a parallel site.

**Fix direction:** Add a language toggle (EN | FR) to the global nav visible on all pages. Ensure `fr/` pages have the same structural nav as English pages. File as P1 if the bilingual claim is used in institutional pitches (library B2B, government partnerships) — the gap between claim and reality is a credibility risk.

**Effort estimate:** Low-Medium for the language toggle; High for full French IA parity (requires translated nav labels and consistent French module structure).

## Finding 5 — B2B entry point absent from main navigation (P2)

**System:** Navigation  
**Dan Brown principle violated:** #5 Front Doors  
**Revenue risk:** B2B / institutional is DCC's primary revenue channel per `_strategy/customer-positioning-draft.md`  

**Observation:** `sitemap.xml` includes `for-libraries.html` and `b2b/index.html`. These pages are not present in the sidebar navigation. They are likely footer-linked only (footer not audited in this pass).

**Problem:** Library staff and community facilitators — the primary B2B customer — arrive at DCC from an institutional pitch email or Google search. If the "For Libraries" page is footer-only, they must scroll to the bottom of any page to find it. A facilitator assessing DCC for their library cannot easily find the facilitator-specific content.

**Fix direction:** Add a "For Libraries" entry to the global nav "Get Started" group, or create a separate audience-switcher at the top of the page (Learner | Facilitator | Organisation). Footer presence should be supplementary, not primary.

**Effort estimate:** Low (one nav item addition).

## Finding 6 — DCC Kids not cross-linked from adult modules for facilitators (P2)

**System:** Navigation + Organisation  
**Dan Brown principle violated:** #6 Multiple Classification  
**Audience:** Library facilitators running mixed-age sessions  

**Observation:** The sidebar "Get Started" section includes a "DCC Kids" link at the global level. However, within adult modules, there are no contextual cross-links to the Kids section (e.g., a facilitator running a family digital literacy session might want to link a parent to an adult module and a child to the kids equivalent).

The Kids section (`kids/4-6/`, `kids/7-9/`, `kids/10-12/`) is a separate site structure with its own index pages. No adult module page points to the kids index or a relevant kids module.

**Problem:** A library facilitator running a multi-age session has no module-level navigation path between the adult and children's content. They must navigate back to the DCC homepage and click "DCC Kids" from there.

**Fix direction:** Add a "Also available for kids" callout in adult modules that are paralleled by a DCC Kids equivalent (e.g., Online Safety, Creating Passwords). Not all 30 adult modules need this — only the ones with a kids parallel.

**Effort estimate:** Low per module, Medium total (requires identifying which adult/kids modules are parallel, then adding callout sections).

## Finding 7 — Noscript navigation is structurally incomplete (P3)

**System:** Navigation  
**WCAG criterion:** 1.3.1 Info and Relationships  

**Observation:** `index.html` contains a `<noscript>` nav block. Analysis shows it lists modules 1–11 and 18–24 only. Modules 12–17, 25–27, and all descriptive-slug modules (`module-fact-check`, `module-ai-health`, `module-visual-ai`) are absent from the noscript nav.

**Problem:** Users with JavaScript disabled (screen reader users, low-bandwidth users, users on restricted library networks) encounter an incomplete navigation structure. 13+ modules are invisible without JavaScript. This is an accessibility and progressive-enhancement failure.

**Fix direction:** Synchronise the noscript nav to match the full sidebar nav. This is a one-time maintenance task — noscript nav must be updated whenever a new module is added (add to the per-module build checklist §9 in DESIGN-SYSTEM.md).

**Effort estimate:** Low (add missing module links to the noscript block; add "update noscript nav" to the build checklist).

## Finding 8 — Module page structure has no "you are here" indicator at category level (P3)

**System:** Navigation  
**Dan Brown principle violated:** #2 Choices (orientation is a prerequisite to choice)  
**WCAG criterion:** 2.4.8 Location  

**Observation:** Module pages display the active module as highlighted in the sidebar. However, there is no breadcrumb or category-level indicator. A user who landed on Module 12 from a search engine sees the module title and the highlighted link in the sidebar — but no indication of which of the five content categories this module belongs to.

**Problem:** The five-category taxonomy (Begin Here / Safety First / Daily Life / Staying Independent / …) exists on the homepage but is invisible on module pages. A senior who arrives cold has no orientation context: "Is this a safety lesson or a daily life lesson? Have I finished this section?"

**Fix direction:** Add a category label above the `<h1>` on each module page (e.g., a small pill/tag: "Daily Life"). This is a display of metadata that already exists in the homepage accordion structure — it just isn't surfaced per-module.

**Effort estimate:** Low per module if added to the DESIGN-SYSTEM.md §4 Module Page Structure template.

## Sidebar Label Review — S-DCC-SIDEBAR-LABELS (2026-06-19)

**Committee:** Founding Board (Sonia, Diana) + Special Advisory (Maya, Kai) + Scrappy Pack  
**Question:** Are the five sidebar labels optimal for DCC's adult seniors audience?

**Current labels:** Get Started / Safety First / Daily Life / Staying Independent / Resources & Help

### Findings

**Keep (consensus):**
- **Get Started** — clear, welcoming, task-oriented. ✓
- **Daily Life** — accurate and plain. ✓
- **Resources & Help** — clear utility label. ✓

**Low-priority optional change:**
- **Safety First** — soft concern: "first" implies ordering that conflicts with "Get Started" coming first in nav; could be "Stay Safe" or "Online Safety." Low priority — does not block implementation.

**Priority change (consensus):**
- **"Staying Independent" → "Living Independently"**
  - "Staying independent" uses medical/policy vocabulary, not seniors' self-description
  - Names a fear (risk of losing independence) rather than describing the content
  - Would be uncomfortable on library promotional materials and institutional partner review screenshots
  - "Living independently" = descriptive-present (this is your life now), not deficit-framing
  - Panel: Sonia, Diana, Maya, Kai, Sage, Tess, Patch all aligned on this change

### Recommendation to Aaron

**One change only:** Rename sidebar category "Staying Independent" → "Living Independently".

Do not change the other four labels. "Safety First" soft-concern is not worth the diff — leave it.

**Implementation:** 1 string change in `index.html` sidebar + same change on all module pages that carry the global nav. Low effort — 30 min max.

**Aaron decision required:** Approve or reject the label change. If approved, implementation is a <1h sprint (S-DCC-SIDEBAR-LABEL-FIX).
