DCC AI help-chat — internal review prototype

Not part of the live site. Not linked from any navigation. For Aaron's review only.

What this is

A working prototype of a floating chat widget that answers digital-literacy questions using an AI service, per the P2 sprint recommending a text-first Cloudflare Worker (see hal-stack/research/dcc-voice-support-shared-vps-feasibility-2026-08-04.md). It has never been deployed anywhere live.

How to try it

1. From digital-confidence/workers/dcc-chat-prototype/, run npx wrangler dev. It will print a local URL, typically http://127.0.0.1:8787.

2. Open this page over HTTP (not file://) with any static server, e.g. from the repo root: python3 -m http.server 8000, then visit http://localhost:8000/v2-lab/ai-chat-demo.html.

3. Click the "Ask DCC" button in the bottom-right corner and type a question, e.g. "How do I know if an email is a scam?"

By default the Worker answers using Cloudflare Workers AI (no API key needed, free at this volume). To try the higher-quality Claude Haiku path instead, run npx wrangler secret put ANTHROPIC_API_KEY in the worker directory before wrangler dev.

Design-gate conflict — flagged, not resolved

PRODUCT.md's own Anti-references list names "Floating overlays that cover content ... these are current anti-patterns already on the live site." This prototype builds exactly the floating-button treatment the sprint asked for, so it can be reviewed as asked — but a filed product doc already calls that treatment an anti-pattern, and this sprint isn't the one authorized to resolve that conflict. Before any production merge, worth deciding whether the chat entry point should instead live in a fixed "designated zone" (nav or footer) per PRODUCT.md principle 4.

Privacy

The widget shows a plain-language notice every time it opens: messages are sent to an AI service to generate a reply, and sensitive information (passwords, account numbers) should not be shared. The Worker stores no message content server-side — only an anonymous per-IP rate-limit counter.
