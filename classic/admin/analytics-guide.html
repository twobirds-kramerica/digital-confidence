Analytics Guide — GA4 Event Reference

Property ID: G-RPH5H5BM52  |  File: js/analytics-events.js  |  Last updated: March 2026

The Digital Confidence Centre uses Google Analytics 4 with custom events defined in js/analytics-events.js. All events use a safe gtag() wrapper that silently fails if GA is not loaded (e.g., when the user has declined consent or is using an ad blocker). Events never block the user interface.

Consent Model

Analytics only fires after the user accepts cookies via the consent banner (js/analytics-consent.js). If the user declines, the GA4 snippet is not loaded and all gtag() calls are no-ops. You may see lower traffic numbers than actual usage — this is expected and correct.

How to View Events in GA4

  1. Go to analytics.google.com and select property G-RPH5H5BM52
  2. In the left menu, click Reports → Engagement → Events
  3. To filter by event name, use the search box or click any event name in the table
  4. For real-time testing: open Reports → Realtime, then open the site in another tab and interact — events should appear within 30 seconds

Custom Dimensions to Register

These parameters are sent with events but will show as (not set) in GA4 until you register them as Custom Dimensions. Do this once in GA4 Admin → Custom Definitions → Custom Dimensions:

Beta Tester Tracking

All events include an is_beta parameter. Users who visit any page with ?beta=true in the URL are tagged as beta testers in localStorage. To create a GA4 segment for beta testers: Explore → Segments → Add segment → Event segment → filter where is_beta = true.

Privacy Notes

  • No personally identifiable information (PII) is sent to GA4
  • User IDs and IP addresses are not logged
  • Analytics only activates after consent is given (see js/analytics-consent.js)
  • If a user declines consent, all gtag() calls are no-ops — verified by checking typeof gtag !== 'function'
